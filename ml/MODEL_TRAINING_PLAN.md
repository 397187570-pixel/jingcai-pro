## 一、当前模型状态（如实评估）

### 1.1 置信度校准 — ✅ 已用真实数据校准

| 项目 | 值 |
|------|-----|
| 校准样本量 | 4,399 场 |
| 数据来源 | 竞彩官方历史接口（webapi.sporttery.cn） |
| 时间范围 | 2025-08 ~ 2026-07（12 个月） |
| 校准 Brier 分数 | 0.0005 |
| 校准方法 | 赔率隐含概率 vs 实际命中率分桶对比 |

**校准表内容**（前端用 `actual` 列作为"真实置信度"）：

| 概率区间 | 预测概率 | 实际命中率 | 样本量 |
|----------|----------|------------|--------|
| 0.3-0.4 | 37.6% | 39.8% | 696 |
| 0.4-0.5 | 44.7% | 43.5% | 1,439 |
| 0.5-0.6 | 55.0% | 51.6% | 1,089 |
| 0.6-0.7 | 64.7% | 66.0% | 745 |
| 0.7-0.8 | 74.6% | 76.4% | 419 |
| 0.8-0.9 | 81.5% | 81.8% | 11 |

**结论**：校准质量优秀，预测概率与实际命中率高度一致。前端显示的"真实置信度"可信。

### 1.2 ML 模型 — ⚠️ 当前用模拟数据训练

| 项目 | 值 |
|------|-----|
| 模型类型 | Softmax 回归（三分类：胜/平/负） |
| 特征数 | 8（elo_diff, elo_home, elo_away, odds_h/d/a, implied_home/away） |
| 训练数据 | **10,000 场模拟数据**（random Elo + 模拟赛果） |
| 真实数据训练 | ❌ 尚未接入 |
| 模型权重可信度 | 低 — 因训练数据为模拟生成 |

**当前系统实际预测路径**：
```
竞彩赔率 → deVig（去水） → 隐含概率 → 查校准表 → 真实置信度
```
ML 模型虽然已加载到前端，但权重来自模拟训练，实际未参与预测链路。**系统当前的预测准确度等同于"赔率去水 + 真实校准"，不依赖 ML 模型**。

### 1.3 回测结论（4,399 场真实数据）

| 策略 | 胜率 | ROI |
|------|------|-----|
| 随机投注 | 33.5% | -10.2% |
| 跟庄（隐含最高） | 52.0% | -12.2% |
| **高置信（≥65%）** | **69.9%** | **-9.6%** |

> 所有策略 ROI 为负 — 因为竞彩抽水 ~12.5%，这是数学必然。但高置信筛选将胜率从 33.5% 提升到 69.9%，相对优势显著。

## 二、模型优化计划（分阶段执行）

### Phase 1：用真实数据重训 ML 模型（预计 2-3 小时）

**目标**：将 mlModel.json 的权重从"模拟数据训练"升级为"4,399 场真实数据训练"

**步骤**：
1. 修改 `ml/train_model.py`，增加 `--real-data` 参数，读取 `ml/data/history_matches.json`
2. 用真实赔率 + Elo 估算 + 赛果标签训练
3. 加入 L2 正则化防止过拟合
4. 5 折交叉验证，报告准确率 + Brier 分数
5. 导出新 mlModel.json

**预期效果**：
- 模型准确率从模拟 ~40% 提升到真实 ~52-55%（接近赔率隐含水平）
- 为 Phase 2 的特征扩展打基础

**特征对齐**（与前端 `fundamentals.js` 一致）：
```
[0] elo_diff      — 主客队 Elo 差
[1] elo_home      — 主队 Elo
[2] elo_away      — 客队 Elo
[3] odds_home     — 竞彩主胜赔率
[4] odds_draw     — 竞彩平局赔率
[5] odds_away     — 竞彩客胜赔率
[6] implied_home  — 隐含主胜概率 1/odds_h
[7] implied_away  — 隐含客胜概率 1/odds_a
```

### Phase 2：扩展特征工程（预计 4-6 小时）

**目标**：从 8 维特征扩展到 15+ 维，引入团队状态、联赛特性

**新增特征**：
```
[8]  home_recent_form   — 主队近 5 场胜率（需历史数据接口）
[9]  away_recent_form   — 客队近 5 场胜率
[10] home_goal_avg     — 主队近 10 场场均进球
[11] away_goal_avg     — 客队近 10 场场均进球
[12] home_concede_avg  — 主队近 10 场场均失球
[13] away_concede_avg  — 客队近 10 场场均失球
[14] h2h_home_winrate  — 近 5 次交锋主胜率
[15] rest_days_home    — 主队休息天数
[16] rest_days_away    — 客队休息天数
```

**数据源**：
- 竞彩官方历史接口（已有 collect_and_calibrate.py）
- football-data.org API（已有 footballData.js 封装）
- 需新建 `ml/collect_team_stats.py` 采集球队近况

**预期效果**：
- 准确率提升 3-5pp（到 55-60%）
- 高置信策略胜率从 69.9% 提升到 72-75%

### Phase 3：升级模型架构（预计 1-2 天）

**目标**：从线性 Softmax 回归升级为梯度提升树

**方案 A：XGBoost（推荐）**
```python
import xgboost as xgb
model = xgb.XGBClassifier(
    n_estimators=200,
    max_depth=4,
    learning_rate=0.1,
    objective='multi:softprob',
    num_class=3
)
```

**方案 B：PyTorch 轻量神经网络**
```python
# 2 层 MLP，输入 16 维 → 隐藏 32 → 输出 3
model = nn.Sequential(
    nn.Linear(16, 32), nn.ReLU(), nn.Dropout(0.2),
    nn.Linear(32, 3)
)
```

**前端推理兼容**：
- XGBoost → 导出为 JSON 规则树，前端用纯 JS 推理（已有 mlModel.js 架构）
- PyTorch → 导出为 ONNX，用 onnxruntime-web 推理

**预期效果**：
- 准确率再提升 2-3pp
- 能捕捉非线性特征交互（如"主场优势 × 联赛类型"）

### Phase 4：实时赔率流 + 在线学习（长期）

**目标**：赔率变动实时影响预测，模型每周增量更新

**架构**：
```
竞彩赔率变动 → 前端实时重算 → 推送预测更新
                 ↓
每周：新赛果入库 → 增量训练 → 更新 mlModel.json + calibration.json
```

**技术方案**：
- SCF 云函数定时触发（每周一 09:00）
- 增量采集上周赛果 → 合并历史数据 → 重训模型 → 更新 CDN
- 前端版本检测 → 自动拉取新模型

## 六、诚实声明

1. **ML 模型当前权重来自模拟数据** — train_model.py 的 `gen_mock_dataset()` 生成随机 Elo + 模拟赛果。权重在数学上是有效的（梯度下降收敛），但不代表真实足球规律。
2. **系统当前预测依赖赔率去水 + 校准表** — 这本身已经是可靠的方法（4,399 场真实校准），不依赖 ML 模型也能给出有意义的置信度。
3. **Phase 1 完成后，ML 模型才能真正参与预测链路** — 届时 `mlModel.predict()` 会用真实数据训练的权重，与赔率去水融合，预期提升 1-2pp。
4. **没有任何模型能突破竞彩 12.5% 抽水的数学限制** — 回测已证明所有策略 ROI 为负。系统价值在于"帮你避开低置信的坑"，而非"预测必中"。
